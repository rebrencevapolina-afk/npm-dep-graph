## Общее описание

CLI-приложение на Python для построения и визуализации графа зависимостей пакетов **npm** (JavaScript). Приложение позволяет:

- Загружать конфигурацию из YAML-файла.
- Получать информацию о прямых зависимостях заданного пакета из реестра npm.
- Строить транзитивный граф зависимостей с учётом максимальной глубины.
- Находить обратные зависимости (пакеты, которые зависят от заданного).
- Визуализировать граф с помощью языка диаграмм D2.

Проект выполнен в рамках дисциплины **«Конфигурационное управление»**.

## Технологии

- **Python 3.10+**
- **PyYAML** — парсинг конфигурации
- **requests** — HTTP-запросы к реестру npm
- **D2** — язык диаграмм для визуализации графа
- **pytest** — тестирование

## Установка и запуск

### 1. Установить зависимости

    py -m pip install -r requirements.txt

### 2. Создать свой `config.yaml`

    cp config.example.yaml config.yaml

### 3. Запустить приложение

    py -m src.main

Вывод должен содержать все параметры в формате ключ-значение:

    ========================================
    Параметры конфигурации:
    ========================================
    package_name = express
    repo_url     = https://registry.npmjs.org
    test_mode    = False
    max_depth    = 3
    ========================================

### 4. Запуск тестов

    py -m pytest tests/ -v

Ожидаемый результат: **10 passed**.

### 5. Обработка ошибок

Приложение валидирует все параметры и сообщает об ошибках:

- Файл не найден.
- Неверный формат YAML.
- Отсутствие обязательных полей.
- Неверный тип поля.
- `max_depth` вне диапазона 1–20.

## Формат `config.example.yaml`

    package_name: "express"
    repo_url: "https://registry.npmjs.org"
    test_mode: false
    max_depth: 3

## Сбор данных (Этап 2)

Приложение запрашивает прямые зависимости пакета из **npm registry** (`https://registry.npmjs.org`).

## Построение графа (Этап 3)

При `test_mode: true` приложение читает локальный YAML-файл и
строит граф зависимостей от заданного пакета методом **BFS с
рекурсией**. Учитывается `max_depth`, обрабатываются циклы.

### Формат тестового файла

    A:
      dependencies: [B, C]
    B:
      dependencies: [D]
    C:
      dependencies: [D, E]
    D:
      dependencies: [A]
    E:
      dependencies: []

### Пример запуска в тестовом режиме

    package_name: "A"
    repo_url: "./tests/fixtures/test_repo.yaml"
    test_mode: true
    max_depth: 3

Вывод:

    ========================================
    Граф зависимостей (5 пакетов):
    ========================================
      A -> B, C
      B -> D
      C -> D, E
      D -> A
      E -> (нет зависимостей)
    ========================================

## Обратные зависимости (Этап 4)

Приложение находит пакеты, которые зависят от заданного пакета
(обратные зависимости). Обход выполняется по тому же графу,
что построен на Этапе 3.

### Пример вывода

    ========================================
    Обратные зависимости для 'A':
    ========================================
      D
    ========================================

### Обработка ошибок

- Файл тестового репозитория не найден.
- Неверный формат YAML.
- Корневой пакет отсутствует в репозитории.
- `max_depth` вне диапазона 1–20.
- Пакет отсутствует в графе.
- Граф пуст.
